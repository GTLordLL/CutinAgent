# 会话管理 — Session 持久化与恢复

## 做了什么

CutinAgent 的会话管理系统负责 **REPL 会话的持久化存储、恢复、列表展示与生命周期管理**。用户在 REPL 中的对话进度不再因退出而丢失——每次退出时自动保存，重新启动后可通过 `/resume` 命令（配合可视化选择器）或 `/resume <id>` 直接恢复到之前的会话状态。

---

## 1. Session JSON 文件格式

每个会话保存为 `user/sessions/{session_id}.json`，包含 7 个字段：

| 字段 | 类型 | 含义 |
|------|------|------|
| `session_id` | string (12hex) | 唯一会话 ID，由 `uuid4().hex[:12]` 生成 |
| `session_name` | string | 会话名称，首次输入消息的前10字符自动命名 |
| `created_at` | string (datetime) | 创建时间，格式 `YYYY-MM-DD HH:MM:SS` |
| `conversation_history` | string | 对话摘要历史（跨 SOP 周期的压缩摘要累积） |
| `execution_history` | string | 执行摘要历史（跨 SOP 周期的操作记录累积） |
| `current_dialogue` | string | 当前未完成轮次的原始对话（User/Agent 消息） |
| `sop_ids` | list[string] | 会话创建时选中的 SOP ID 列表 |

### 字段与 OverallState 的对应关系

| JSON 字段 | State 字段 | 说明 |
|-----------|-----------|------|
| `session_id` | `state["session_id"]` | 会话 ID |
| `session_name` | `state["session_name"]` | 会话名称 |
| `conversation_history` | `state["conversation_history"]` | 对话历史 |
| `execution_history` | `state["execution_history"]` | 执行历史 |
| `current_dialogue` | `state["current_dialogue"]` | 当前对话 |
| `sop_ids` | `state["sop_ids"]` | 选中启用的 SOP ID 列表 |

> **为什么保存 `sop_ids`？** 恢复历史会话时，如果 SOP 库已发生变化（新增/删除了 SOP），旧会话中 UserCoordinator 引用过的 SOP_ID 可能已不存在。保存会话创建时选中的 SOP ID 列表（而非完整 SOP 库文本）既保证了会话恢复后 SOP 匹配的一致性，也避免了将大量 SOP 库文本存入每个会话文件。注意：早期版本的会话 JSON 使用 `sop_library_text`（完整 SOP 库文本快照）存储，`load_session()` 包含向后兼容逻辑——当 `sop_ids` 为空而 `sop_library_text` 存在时，自动从旧格式解析出 SOP ID 列表。

## 2. 存储位置

```
user/sessions/
├── a1b2c3d4e5f6.json
├── f6e5d4c3b2a1.json
└── ...
```

- **目录**：`user/sessions/`（由 `_get_sessions_dir()` 确保存在）
- **文件名**：`{session_id}.json`（12 位 hex + `.json`）
- **编码**：UTF-8，`ensure_ascii=False`

## 3. CRUD 操作

所有操作实现在 `repl/session_manager.py`，调用方通过 `repl/__init__.py` 导入。

### 3.1 `save_session(state) → str | None`

将当前 state 的 7 个会话字段写入 JSON 文件。如 `session_id` 为空则自动生成，`session_name` 为空则设为 `"Unnamed"`。返回 `session_id`，失败返回 `None`。

调用点：
- `/clear` 命令：保存旧会话后开启新会话
- `/resume` 命令（选择器）：自动保存当前会话再打开选择器
- `/resume <id>` 命令：自动保存当前会话再加载目标会话
- 退出 REPL（Ctrl+C）：`finally` 块中自动保存

### 3.2 `load_session(session_id) → dict | None`

从 `user/sessions/{session_id}.json` 读取并返回包含 7 个会话字段的 dict。文件不存在、JSON 损坏、其他异常均返回 `None`（错误在调用方处理，不在 session_manager 内部打印）。

### 3.3 `list_sessions() → list[dict]`

列出所有已保存会话，返回 `[{"session_id", "session_name", "created_at"}, ...]`，按 `created_at` 降序排列。损坏的 JSON 文件自动跳过。

### 3.4 `delete_session(session_id) → bool`

删除指定会话文件。文件不存在返回 `False`。

## 4. 会话选择器 UI

会话选择器是一个 **prompt_toolkit ConditionalContainer**，在 `/resume`（无参数）命令触发时覆盖底部状态栏区域。

### 4.1 布局切换机制

```
正常状态：                    选择器激活：
  ─────────────────────           ─────────────────────
    输入区域 (TextArea)              输入区域 (TextArea)
  ─────────────────────           ─────────────────────
    状态栏 (height=2)                会话选择器 (height=8)
     picker_filter=~active           picker_filter=active
```

`ConditionalContainer` 通过 `picker_filter=Condition(lambda: picker_state["active"])` 动态切换底部显示内容。选择器激活时，状态栏被隐藏；选择器取消/确认后，状态栏恢复。

### 4.2 选择器尺寸

| 常量 | 值 | 说明 |
|------|-----|------|
| `PICKER_HEIGHT` | 8 | 选择器窗口高度（行） |
| `SESSIONS_PER_PAGE` | 5 | 每页显示的会话数 |

### 4.3 键位绑定

| 按键 | 操作 | 说明 |
|------|------|------|
| ↑ | `picker_move_up` | 上移高亮项 |
| ↓ | `picker_move_down` | 下移高亮项 |
| ← | `picker_page_left` | 翻到上一页 |
| → | `picker_page_right` | 翻到下一页 |
| Enter | `picker_select` | 确认选择当前高亮会话 |
| Esc | `picker_cancel` | 取消选择 |

> **Picker 按键的 filter 条件**：所有 picker 按键绑定只在 `picker_filter`（即 `picker_state["active"]` 为 `True`）时生效，确保正常输入不受影响。Enter 键在 Picker 激活时也会先清空输入区文本再触发选择，避免残留文本干扰。

### 4.4 异步等待机制

Picker 使用 `asyncio.Event` 模式等待用户选择：

1. `activate_picker()` 设置 `result_event` 为未触发状态
2. REPL 循环 `await picker_state["result_event"].wait()` 阻塞等待
3. 用户按 Enter（`picker_select`）或 Esc（`picker_cancel`）时 `result_event.set()`
4. `deactivate_picker()` 关闭选择器并返回 `result` dict

```python
# result dict 格式：
# {"action": "select", "session_id": "a1b2c3d4e5f6"}   # 确认选择
# {"action": "cancel"}                                     # 取消
```

### 4.5 mutable-dict 模式

与 `status_data` / `top_status_data` 一致，`picker_state` 使用可变字典存储状态，`FormattedTextControl` 通过闭包 lambda 引用 dict 来动态渲染。修改 `picker_state` 后调用 `app.invalidate()` 即可刷新显示。

## 5. REPL 命令与会话操作

### 5.1 `/clear` — 保存旧会话 + 开启新会话

```
1. 检查 current_dialogue / conversation_history / execution_history 是否有内容
2. 有内容 → save_session(state) 保存旧会话
3. create_session_dir() 创建新目录
4. generate_session_id() 生成新 session_id
5. 重置 state 中的所有会话字段
6. 清空 token 显示
```

### 5.2 `/resume` — 打开会话选择器

```
1. list_sessions() 获取所有已保存会话
2. 无会话 → 提示用户使用 /clear
3. 有会话 → 先 save_session(state) 保存当前会话（脏检查）
4. activate_picker() 打开选择器
5. 等待用户选择（await result_event）
6. 选择 → load_session(session_id) → 恢复字段到 state
7. 取消 → 不做任何操作
```

### 5.3 `/resume <session_id>` — 直接加载指定会话

```
1. 脏检查 + 自动保存当前会话
2. load_session(session_id) 直接加载
3. 恢复 6 个字段到 state
4. 清空 token 显示
```

## 6. 退出自动保存

REPL 退出时（Ctrl+C 或 `/exit`），`finally` 块中执行：

```python
if (state.get("conversation_history", "").strip() or
    state.get("execution_history", "").strip() or
    state.get("current_dialogue", "").strip()):
    save_session(state)
```

三个字段全部为空时跳过保存（用户刚启动就退出，没有产生任何对话）。

---

## 7. 自动命名策略

首次用户输入时自动命名：

```python
if not state.get("session_name", ""):
    clean = user_msg.strip()
    state["session_name"] = clean[:10] if clean else "Unnamed"

if not state.get("session_id", ""):
    state["session_id"] = generate_session_id()
```

- 取用户首条消息的前 10 个字符作为会话名
- `session_id` 在首次输入时生成（而非 REPL 启动时），避免空会话占用 ID

## 8. 边界情况表

| 场景 | 行为 |
|------|------|
| `/resume` 但 `user/sessions/` 无会话 | 提示使用 `/clear` 开始新会话 |
| `/resume <id>` 但文件不存在 | 显示错误，不恢复 |
| `/resume <id>` 但 JSON 损坏 | 显示错误，不恢复 |
| `/resume` 选择器打开中按 Esc | 取消选择，保持当前会话 |
| `/clear` 但当前无内容 | 直接创建新会话，不保存 |
| `/resume` 打开选择器，当前有未保存内容 | 先自动保存当前会话再打开 |
| 退出时无任何对话 | 跳过自动保存 |
| SOP 库已更新后恢复旧会话 | 使用旧会话中的 sop_ids 列表（含旧格式向后兼容） |

---

## 9. 为什么这么做

### 会话恢复需要 SOP ID 快照

如果恢复时不保存会话的 SOP 选择状态，而当前 SOP 库已发生变化（新增/删除了 SOP），旧会话中 UserCoordinator 引用过的 SOP_ID 可能指向不同的 SOP 或不存在。保存 `sop_ids` 列表（而非完整 SOP 库文本）是更精确的做法——恢复会话时只恢复用户当时选择的 SOP 集合，既保证了完整性又避免了将大量 SOP 库文本存入每个会话文件。`load_session()` 包含向后兼容逻辑，可自动将旧格式的 `sop_library_text` 转换为 `sop_ids`。

### Picker 使用 asyncio.Event 而非嵌套 Application

会话选择器复用现有的 prompt_toolkit Application 和 `ConditionalContainer` 机制，而非创建新的临时 Application。这避免了嵌套事件循环问题，且与现有的按键绑定系统无缝集成。

### 脏检查而非每次操作都保存

只在确实有内容变化时才保存（三个对话字段任一非空）。如果用户在 `/clear` → `/resume` → `/clear` 之间来回切换而没有实际对话，不会产生大量空会话文件。

### CRUD 函数返回错误值而非直接打印

`session_manager.py` 作为数据层，通过返回值（`None`、`False`）传递错误信息，由调用方（main.py）决定如何展示。错误信息可包含具体的 session_id 等上下文，这比 session_manager 内部 print 更灵活。
