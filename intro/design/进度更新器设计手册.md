# 进度更新器设计手册

ProgressUpdater 是纯 Python 代码节点，负责在每轮工具执行后将工具的执行结果追加到 SOP_PLAN 对应步骤行尾。目的是为了精简上下文和记录运行状态和关键数据。

## 一、处理流程

```
三字段 (status/summary/detail_var) → _format_result 拼接 → 检测是否已有结果 → 选择追加模式 → 更新 step header
```

### 1.1 工具输出三字段

工具返回三字段 dict：`{"status": "成功|失败", "summary": "...", "detail": "..."}`

| 字段 | 含义 | 说明 |
|------|------|------|
| `status` | `"成功"` 或 `"失败"` | 判定工具是否正常执行 |
| `summary` | 结论/原因 | 一句话结论或失败原因，直接追加到 SOP_PLAN |
| `detail` | 详细数据 | 完整原始数据（如 git diff 全文），非空时由 ToolExecutor 存入 VariableStore |

`_format_result(status, summary, detail_var)` 将三字段拼接为追加文本：
- **失败**: `失败 | summary`（丢弃 detail 和变量引用）
- **成功**: `成功 | summary`（summary 非空时）+ ` [变量: VAR_xxx]`（变量名非空时）

### 1.2 已有结果检测 (`_already_has_result`)

检测目标步骤的 header 是否已包含 `结果:` 标记。
- 已有 `结果:` → 非首次执行，走重试计数逻辑（剥离旧标记 + 追加新结果 + 递增 `重试 N/M`）
- 无 `结果:` → 首次执行，走正常追加逻辑（顺序/条件/并行）

### 1.3 跳过间隙填充 (`_fill_skipped_gaps`)

在更新当前步骤之前，检查上一个已标记步骤和当前步骤之间是否有未标记的步骤。
若有，将它们标记为 `已跳过（条件不满足）。`

示例：步骤1、3 已标记，当前目标为步骤4 → 步骤2（未标记）被填充为跳过。

## 二、四种追加模式

### 2.1 顺序追加 (`_update_sequential`)

适用于 SEQUENTIAL 和 PARALLEL 类型，且执行成功时。

```
改前：1. 调用 run_command(command='ss -tlnp | grep :22')
改后：1. 调用 run_command(command='ss -tlnp | grep :22') 结果: 成功 | 命令完成 (exit 0), 1 行输出, 耗时 0.1秒 | 端口22 LISTEN [变量: VAR_run_command]。
```

### 2.2 条件追加 (`_update_conditional`)

适用于 CONDITIONAL 类型，且执行成功时。
从 step header 中匹配分支条件，根据实际调用的 tool_id 确定命中分支。

```
改前：2. 如果端口80有监听，就调用 run_command(command='systemctl status nginx')。如果端口22有监听，就调用 run_command(command='systemctl status sshd')。
改后：2. 因为端口80有监听，所以调用 run_command(command='systemctl status nginx') 结果: 成功 | 命令完成 (exit 0), 3 行输出, 耗时 0.2秒 | Active: active (running) [变量: VAR_run_command]。
```

若无法匹配到具体分支，退化为顺序追加格式。

### 2.3 并行追加

与顺序追加相同（`_update_sequential`），适用于 PARALLEL 类型。

```
改前：3. 同时调用 get_git_status() 和 get_git_diff(staged=False)，并行采集工作区状态和代码变更。
改后：3. 同时调用 get_git_status() 和 get_git_diff(staged=False)，并行采集工作区状态和代码变更 结果: 成功 | 分支 'master' 有未提交变更 | 已暂存 0、未跟踪 2 [变量: VAR_get_git_status]。
```

### 2.4 重试计数 (`_update_with_retry`)

适用于步骤已有 `结果:` 标记时（即非首次执行）。无论当前执行成功或失败，都先剥离旧的重试/结果/跳过标记，保留原始步骤描述，然后追加新结果并递增重试计数。

**未达上限**：
```
1. 调用 xxx(a=1) 结果: 失败 | 权限不足。重试 1/3
```

**再次失败**：
```
1. 调用 xxx(a=1) 结果: 失败 | 权限不足。重试 2/3
```

**达到上限**：
```
1. 调用 xxx(a=1) 结果: 失败 | 权限不足。已达到重试上限（3次），当前步骤不允许再次重试。
```

重试次数通过 `_extract_retry_count()` 从 header 中正则提取 `重试 N/M`，未找到返回 0。

## 三、Plan 文本解析

### 3.1 步骤解析 (`_parse_steps`)

将 SOP_PLAN 文本按 `N. ` 行头拆分为步骤块列表。每块包含：
- `number`: 步骤序号
- `header`: 步骤第一行内容（不含序号前缀）
- `sub_lines`: 步骤的后续行（多行步骤内容）

### 3.2 步骤重构 (`_reconstruct_plan`)

将步骤块列表重建为完整的 SOP_PLAN 文本字符串。

---

## 四、状态标记

`_is_step_marked()` 通过检测以下关键词判断步骤是否已有状态：
- `结果:`
- `已跳过`
- `重试 `
- `已达到重试上限`
